# Synthetic trips dataset (AI-05)

> **This data is fake.** Every trip, location, hour and travel time is generated by
> `ml/eta/synthetic.py` from an invented model. No real patients, trips, addresses
> or traffic measurements are used. Results on this data must **not** be described
> as validated real-world traffic predictions. ETAs are estimates, not guaranteed
> arrival times, and this project is not for real emergency dispatch.

## How to create and use it

From the project folder, with the virtual environment active:

```
python -m ml.eta.synthetic     # writes data/synthetic_trips.csv (1000 trips, seed 42)
python -m ml.eta.evaluate      # writes data/baseline_metrics.json and data/baseline_examples.csv
```

Both scripts run top to bottom with no other setup. `--rows` and `--seed` change the
size and the random seed of the dataset (for example `--rows 500 --seed 7`).

## Fields (one row = one trip)

| Column | Type | Meaning |
|---|---|---|
| `tripId` | whole number | 1, 2, 3, ... (unique) |
| `dataSource` | text | always `synthetic` |
| `fromLat`, `fromLng` | decimal degrees | Start point (6 decimals) |
| `toLat`, `toLng` | decimal degrees | End point (6 decimals) |
| `distanceKm` | number | Straight-line (Haversine) distance between the points, 3 decimals |
| `hour` | whole number 0-23 | Hour of the day the trip starts |
| `dayOfWeek` | whole number 0-6 | 0 = Monday ... 6 = Sunday |
| `ambulanceType` | text | always `BLS` (the only supported type for now) |
| `trafficLevel` | text | `low`, `medium` or `high` |
| `roadType` | text | `local`, `arterial` or `highway` (the main road type of the trip) |
| `travelTimeMinutes` | number | The target: the "true" travel time in minutes, 2 decimals |

The names `fromLat`, `fromLng`, `toLat`, `toLng`, `hour` and `ambulanceType` are the same
as in the API request, so they cannot be mixed up later.

## How one trip is generated (all numbers are invented assumptions)

1. **Locations.** The start point is drawn uniformly inside an arbitrary rectangle
   (latitude 28.40 to 28.88, longitude 76.84 to 77.35, about the size of a large city).
   The end point is the start plus a random offset of up to 0.15 degrees in each
   direction. If the end point leaves the rectangle, or the trip is shorter than
   0.5 km, the trip is drawn again. Resulting distances run from about 0.5 to 22 km.
2. **Hour and day.** Both are drawn uniformly (every hour and every day equally likely).
3. **Traffic level.** Drawn at random with these probabilities (low / medium / high):

   | Situation | low | medium | high |
   |---|---|---|---|
   | Night (hours 0-5) | 0.90 | 0.09 | 0.01 |
   | Weekday rush (hours 8-10, 17-20) | 0.10 | 0.30 | 0.60 |
   | Weekday other | 0.45 | 0.45 | 0.10 |
   | Weekend rush (hours 8-10, 17-20) | 0.40 | 0.40 | 0.20 |
   | Weekend other | 0.65 | 0.30 | 0.05 |

4. **Road type.** Drawn independently of distance: local 35%, arterial 45%, highway 20%.
5. **Travel time.**

```
   road distance   = straight distance x detour factor   (local 1.40, arterial 1.25, highway 1.15)
   speed           = base speed x traffic factor
                     base speed:     local 30, arterial 45, highway 65 km/h
                     traffic factor: low 1.0, medium 0.8, high 0.55
   noiseless time  = road distance / speed x 60  +  1 minute start-up time
   travelTimeMinutes = noiseless time x noise
```

   Worked example: 10 km straight line, arterial road, medium traffic gives
   12.5 km of road at 36 km/h, which is 20.83 minutes, plus 1 minute, so 21.83 minutes
   before noise.

## Noise

The noise is multiplicative and log-normal: `noise = exp(Normal(0, 0.12))`. Its median is 1,
so on its own it neither raises nor lowers times; it makes a typical trip about 12% faster
or slower than the model says (and can never make a time negative). The tests check that
the spread of the data really matches this value (`NOISE_SIGMA` in `synthetic.py`).

## How the baseline is evaluated

* The 1000 trips are split once into 800 training and 200 validation trips, at random with
  seed 42 (`split_train_validation` in `evaluate.py`). Phase 4 reuses the same function, so
  the model never trains on validation trips.
* The baseline has nothing to train, so it is scored only on the 200 validation trips,
  using the real `predict_eta` function.
* The main number is **MAE** (mean absolute error): the average of
  `|baseline ETA - true travel time|` in minutes. It is saved in `data/baseline_metrics.json`
  together with the bias (mean signed error; negative means the baseline is too low on
  average) and the MAE for peak and off-peak hours.
* 20 randomly chosen (not hand-picked) validation trips, with the baseline's prediction and
  its error, are saved in `data/baseline_examples.csv`.

## Assumptions and limitations

* **Everything is invented.** The detour factors, speeds, traffic probabilities, start-up
  time and noise are made-up values, not measurements. The MAE only measures the baseline
  against this invented world, not against real roads or real ambulances.
* **The baseline and the dataset use two different sets of invented numbers.** The baseline
  assumes 25 or 40 km/h on straight lines; the dataset has detours, road types, traffic and
  start-up time. A large gap between them says the two sets of assumptions disagree, not that
  one of them is right. The baseline's speeds and peak hours are themselves assumptions(accepted by the mentor,not measured).
* **The dataset agrees with the baseline about which hours are busy.** Rush hours are the
  same as the baseline's peak hours. This makes the baseline's hour assumption look better
  than it may be in reality.
* **Simplified world.** No weather, no incidents, no real road network, no one-way streets,
  no traffic lights, no distance-dependent road type, one ambulance type, uniform hours and
  days (real emergency calls are not uniform).
* **Fake geography.** The rectangle is arbitrary and the points are not real incident
  locations.
* **Hidden fields.** `trafficLevel`, `roadType` and `dayOfWeek` are in the dataset, but the
  API will only receive coordinates, hour and ambulance type. A model that has to work behind
  the API cannot use them at prediction time. `ambulanceType` is always `BLS`, so it carries
  no information.
* **Reproducibility.** The same code, seed and library versions give the same dataset. A
  different NumPy version may in principle give slightly different random numbers (and so a
  slightly different MAE).
* **Accepted by the mentor:** the peak hours, the baseline speeds, and the integer hour.
  They are still assumptions, not measured data. **Not yet confirmed with Naga:** the
  decision to return 0.0 for identical start and end points, and that `BLS` must be
  exactly uppercase.
